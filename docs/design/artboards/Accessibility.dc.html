Lists and message stacks are one tab stop each, with arrow keys inside. Tabbing through 50 rows to reach a button is technically accessible and practically unusable — and this is the single most common accessibility failure in a custom mail list. Focus is remembered when you leave and come back to a region.

What a screen reader says
thread row → "Unread. Reklamation: utætte samlinger efter montage. 6 messages, 2 unread. Latest from Morten Bach Jensen, 10 September 10:33. Has attachments. 1 of 3."
message → "Received from Kim Petersen, external sender, 10 September 07:55. To Care, copy Morten Bach Jensen and Anne Holm. Unread. Collapsed."
fold → "Show trimmed content, 3 earlier messages quoted. Collapsed. Button."
live region → "Queued. Not sent yet." … then … "Sent." Announced, because the send ladder changes on its own and a sighted agent sees it while a screen-reader user would not.
Every icon-only control carries a real name — no "button button". Direction, read state and external-sender are spoken, not only coloured.

Never colour alone. Unread is a dot and bold weight and an edge bar. Direction is a coloured arrow and its shape. Both survive a greyscale print and both survive colour blindness. Audit, don't assume. These are computed pairs; the build must re-run them with Accessibility Insights on the real rendered control, in both themes. A sender's own HTML is out of scope — we cannot fix their contrast, but we must not make it worse.
