The honest part: "about 25 MB" is hedged deliberately. We measured that a 40 MB file stores fine, but never measured what transport will actually deliver, and the recipient's server has its own limit we cannot see. Once one real send has been measured, this states a firm number. Until then it must not invent one — a confident wrong limit is worse than an honest approximate one, and R13 only requires the limit be stated explicitly.
No admin change is needed for large files. The 5 MB organisation limit applies only to the simple upload path; the chunked path we use is not bound by it — measured at 40 MB. So this is built without asking anyone to raise a tenant-wide setting, which matters in a shared environment.
Storing is not sending. Those are two different limits and the interface must not conflate them: a file can be attached to the draft successfully and still be rejected in transit. The send result is the only place that truth appears — see the send ladder.
