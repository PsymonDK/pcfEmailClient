The table scrolls inside the message. The app layout never moves. That is the whole rule: a sender's HTML may be any width, and the failure everyone ships is letting it push the page sideways.
The inline photo renders in the body and does not also appear as a downloadable chip. It is the same stored file as an attachment row — listing it twice is a real bug the fixture is built to catch.
Before it is rendered, it is sanitised These bodies were written by people outside the organisation and land in a page holding the agent's own Dynamics session. Rendering them raw is a cross-site-scripting hole with the agent's permissions behind it. So every body passes through an allow-list first. That is a build requirement, not a nicety — and it is why the dashed container above is drawn at all.
What survives sanitising, and why
KEEPTables and all their parts — half of B2B mail is a table.
KEEPImages, and the id and class attributes. Those attributes look like clutter but the quote and notice detection matches on divRplyFwdMsg, gmail_quote and the Defender markers — strip them and R4, R12 and R21 all stop working at once, silently.
KEEPThe style attribute, property-filtered. Senders colour and align things and it carries meaning.
DROPScripts, event handlers, forms, inputs, frames, embeds — and the <style> tag. A sender's stylesheet is unscoped and would restyle the Dynamics chrome around us.
DROPAny URL that is not http(s), mailto, tel, cid or a raster data image. SVG data URIs carry script.
ADDLinks get rel="noopener" and open in a new tab — otherwise a link in hostile mail gets a handle on the session window.
Containment — separate from sanitising, also required Sanitising stops script. It does nothing about a 1400px table, a 96px heading or a black-on-black colour choice. So the body sits in its own container with a font and colour reset, max-width 100% and overflow-x: auto on its descendants. Two failures to test for explicitly: a table wider than the pane (above), and a sender who sets white text — which must not become invisible against our background.
Inline images need resolving, not just allowing A cid: reference is not a URL a browser can fetch. Allowing the scheme only stops the image being thrown away; it still has to be matched to the stored attachment it points at and swapped for something renderable. An image that cannot be resolved shows a labelled placeholder — never a broken-image icon, which reads as "our client is broken" rather than "that attachment is missing".
Bodies are fetched one at a time, on expand. Email bodies now live in blob storage rather than the database, so pulling them for a whole thread up front is what makes a 50-message case slow. Never in the list query.
