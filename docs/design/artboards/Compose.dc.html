1
Context bar. Which message is being answered, which mailbox it goes out from, and that the mailbox is approved — the pre-flight result, shown before Send is ever pressed.
2
Recipients as chips. Pre-resolved by reply-all rules. Removable individually. Subject is hidden by default — it is inherited, and editing it breaks threading, so it is behind a link.
3
One toolbar row, fixed height. Everything beyond this row lives in the overflow menu. A toolbar that wraps to two lines silently eats the editor.
4
The editor — 66px, about 3 lines. This is the honest cost of docking. It grows as you type, taking space from the thread above, up to half the pane. Beyond that, pop out.
5
The quote, outside the editor. Read-only, folded, appended verbatim at send. The agent can see it is there and read it, but cannot edit it — by design.
6
Send row, always visible. Never scrolls away. Discard is text, not a button — it is destructive and should not sit at the same weight as Send.
Look at ④ and judge it honestly Three lines of visible text. That is what 222px buys after the context bar, recipients, toolbar, quote strip and send row have taken their fixed share. For "we'll send someone tomorrow" that is plenty, and it is most replies. For a careful explanation of a disputed invoice it is not, and the honest answer is pop out rather than pretending. If this looks too tight to you, the lever is not making compose taller — the thread above would disappear, and seeing what you are answering is the point of composing in place. The lever is the overlay option, below.
It grows while you type
222px · 3 lines · opens here
~300px · 7 lines · as you pass line 3
~380px · the ceiling · half the pane
beyond that, the editor scrolls — or pop out
It never shrinks back while you are writing. Layout that jumps under the cursor is worse than layout that is slightly too small.
What the editor is, technically Not the platform's rich-text control — that was tested and cannot be reused here. A bundled editor core, mounted by hand, with the toolbar above drawn by us. Which core is a measured decision, not an opinion: three candidates get built into a throwaway bundle and the one with an acceptable size wins, preferring the ones that emit clean predictable HTML. Paste from Word is the acceptance test that matters. It is also the reason the quote stays outside — an editor strict enough to clean up Word's markup is strict enough to rewrite a customer's quoted chain.

For: roughly twice the typing room, and it does not squeeze the thread — it covers it. Against: it covers the thing being replied to. Agents check what the customer actually asked while answering — that is the behaviour the whole in-place idea exists to serve, and an overlay takes it away. It also blocks the thread list, so nothing else on the case can be read mid-reply.
Recommendation: keep docked, keep pop-out. That gives the common case a surface that never hides context, and the rare long reply a proper window — with no third layout to build or maintain.
