Where reply comes from Three entry points, all reaching the same docked surface: the per-message icons at the right of each message row, the thread-level Reply all button in the card header, and Ctrl+R / Ctrl+Shift+R. Whichever is used, the header says which message is being answered — "replying to Kim Petersen" — because in a six-message thread that is genuinely ambiguous and getting it wrong sends an answer to the wrong person.
Pop out is the escape hatch for a long reply: the same draft, in a dialog, with room. It writes the same draft row, so closing it loses nothing.

OUTCare — our own sending mailbox. Never reply to ourselves.
OUTLene Sørensen — the agent's own address, if it appears anywhere.
OUTAny Bcc from the original. Bcc never propagates — carrying it forward discloses a hidden recipient.
Duplicates are removed case-insensitively on the address, not the display name — the same person often appears under two spellings across a chain.
The quote is not in the editor The agent edits only their own new text. The inherited chain sits below the editor as a folded, read-only strip and is appended untouched when the message is sent. This is the most important compose decision in the build. A rich-text editor that ingests arbitrary Outlook HTML will re-write it — reindenting, dropping styles, mangling tables — and R12 requires the prior chain to survive intact. Keeping it out of the editor turns "must round-trip anyone's HTML", which no editor does well, into "must handle what the agent types", which they all do.
The signature is editable, inserted from the agent's default on open, and shown in grey so it reads as boilerplate rather than as something they wrote. "Saved 14:58" is not decoration — the draft is written to the case on blur and on a timer, so switching case or closing the browser does not lose it.
