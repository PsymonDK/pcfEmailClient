the same component, same build 1627 × 536 px
No process bar, no other tabs — and yet the same 536px. The chrome we lose is offset by the record header still being there. The 27px width difference is not a design problem. So there is one set of screens, not two.

Three rules that fall out of this, and they are binding on the build: 1. Exactly one scroll region per card. A scrollbar inside a scrollbar is the failure mode this budget exists to prevent. 2. Nothing above the scroll region may grow. Header, search and chips are fixed heights; a wrapping toolbar silently eats the reading area. 3. Compose is docked, not overlaid. At 220px it still leaves the thread readable — which is R10's whole point. An overlay would cover the thing the agent is replying to.

Why 900 and not a guess: the list needs 424px to keep subject and snippet legible, and a body needs ~420px before Outlook tables and quoted headers start wrapping badly. Below their sum, showing both costs more than it gives. Selecting a thread swaps the column and offers a back control, so no state is lost — the same selection, one pane at a time. This is reachable in practice: a half-screen browser, or a second monitor at 1280. It is not a phone case — Copilot Service Workspace is not used on phones.
