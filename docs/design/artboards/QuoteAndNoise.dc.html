Expanded, the quote is rendered exactly as received — indented by nesting depth, never re-serialised. The build rule behind this is that we display the quoted region and never rewrite it.
Detection rules, in order of confidence
CERTAIN Defender banner — matched on the ZjQcmQRYFpfptBannerStart / …End markers. Whole marked region folds. Same for the first-contact tip wrapper and the classification line pattern.
STRONG Quoted history — div#divRplyFwdMsg, .gmail_quote, -----Original Message----- in seven localisations, an <hr> followed by a bolded Fra:/From:/Von: block. Folds.
WEAK A bare <blockquote> — used for quoting, but also for emphasis. Folds only when it is the last block and longer than the text above it.
GUESS Signature blocks. Never folded — de-emphasised only.
The rule that governs all of them When confidence is low, show the content. A visible banner is clutter; a hidden paragraph is a mishandled case. Those are not equally bad, so the failure is asymmetric and the default must lean the same way. Nothing is ever deleted — every fold is one click from being open, and the fold state persists per agent, so anyone who prefers the raw message gets it. This is a heuristic, not an API. Dataverse stores one HTML body with no marker for where a quote begins; there is no platform call that answers this. It scored 10/10 against the one real delivered message we measured, and it will meet mail it has not seen. The affordance is what makes that survivable.
